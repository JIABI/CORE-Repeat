# 固定核心架构与跨数据模块验证

2026-09-16。本文件固定下一阶段的方法与决策规则，不修改原 OPAL 1.0 合同或既有结果；新评价人群、单一部署拟合实例与统计采样方案尚待确定。当前1188个LINCS对象和639个JUMP对象继续作为已经开发过的数据，不能通过重新分区变为独立外部验证。

## 一、固定基础方法

基础方法命名为 **STATE50 + conditional empirical-radial measurement model**。这里的generic指不使用新增靶点/MoA或JEPA模块的完整基础流程，不是上一轮表现下降的 `GENERIC` logistic 概率读出。

其结构是：

第一孔形态、幅度及既有合法化学/参考信息 → 固定训练配方的STATE50几何均值 → 参考残差估计的条件散布及幅度尺度 → 幅度条件经验径向分布 → 合法四孔Gram样本 → 原Γ与NULL概率 → 固定预算风险惩罚排序。

- 均值：Ridge/HR与完整A的既有层级保留；STATE50为同一A上的第一孔状态调制修正。原数据采用第50轮，不事后切成验证最优轮次。PCA8+log幅度只从相应FIT估计。
- 预测对象：九维标准化log-Cholesky几何，采样后恢复合法Gram；原ADD_TWO终点不变。它不是可直接支持任何组学终点的通用谱生成器。
- 联合分布：保留AMP_EMP_LOCAL配方。散布和幅度函数在REF_FIT估计，径向律在独立DIST_CAL估计；不能为了让所有名字都叫FIT而改为拟合内残差。
- 径向律：90%平滑经验半径与10%高斯半径后备；原紧支撑log三角核带宽；按第一孔log幅度加权，以ESS/(ESS+20)向总体收缩。均匀球面方向是模型假设，既有方向失配结果仍保留。
- 决策：固定 `score = E[Γ] − 0.2 P(Γ≤0)`。λ=0.2来自已经看过的开发证据和风险偏好，**不是从未接触数据前提出的值**；新评价中不再选择它。
- 预算：先声明每个真实campaign的整数追加孔预算B，ADD_TWO每对象2孔，选择 `min(N, floor(B/2))` 个。主计划B=floor(0.25N)。排序并列按稳定对象ID。旧十单元146对象的配额按原分配重放，不悄悄换成每半组ceil(0.125N)。
- 正式新运行统一每对象100,000次联合抽样，固定随机方案，不能依赖实际Γ改变精度或删样本。旧10,000次报告不被覆盖。

主模型关闭生物关系与JEPA。原Gaussian、同径向模型λ=0、同预算随机、不追加以及全追加（预算不匹配的参考）预先列为必要对照。不能在新评价上挑其中最好的一条再称主要策略。

当前保存的状态是五个外折模型和十套参考径向律，不是一个已经训练完成的新部署模型。算法配置见 `configs/core_policy_20260916.json`；单一部署权重、参考身份和CDF必须在新评价结果打开之前另行固定。

## 二、参考隔离与数据用途

必须区分模型训练、参考拟合、分布校准、策略校准和最终评价。只写“训练/测试不重叠”不足以约束推理时参考库。

| 角色 | 可以做什么 | 不可以做什么 |
|---|---|---|
| MODEL_FIT | 预处理、均值和表示拟合 | 使用EVAL未来测量或收益 |
| REF_FIT | 条件残差、散布、幅度函数和参考检索；对残差采用合法留出/折外预测 | 把自己的拟合内残差冒充独立预测误差 |
| DIST_CAL | 固定均值/尺度之后估径向律；其信息可作为已声明预测器的一部分 | 再把同一批对象当独立最终评价或独立策略校准 |
| POLICY_CAL | 若另有必须选择的策略参数，在完全固定的预测器上选择 | 回流进入该预测器的均值、参考、尺度或径向律 |
| EVAL | 决策时仅提供合法X、条件和预先允许的元数据；开盲后评价 | 在冻结前提供未来孔、Γ或被用作其他查询的结果参考 |

本方案λ固定，不需要为λ额外选择一份POLICY_CAL。但DIST_CAL仍是必需角色；不能要求所有CAL永远不影响预测器，否则经验径向校准本身就无法实现。若某个目标实验室提供独立参考面板，应计费并登记，不能从EVAL对象的未来测量中冒充取得。

身份隔离须同时检查化合物组。共享实验板、日期、位置造成的依赖另行处理；对象ID不重叠不等于实验独立。禁止重用当前相反查询半组的缓存预测来选择策略参数。

## 三、固定预算与统计推断

固定top-k有实际预算意义，但“k固定，所以NULL个数是二项分布”不成立。即使给定所有X后各对象独立，它们的NULL概率也未必相同，计数一般是Poisson-binomial；共享板和整体排序还会引入其他依赖。因此新策略接口明确禁止直接调用旧点式IID CP认证。

本轮固定的是**分配方式**，没有宣称完成新的认证定理。对一个全数观测的有限campaign，可以准确报告该campaign的实际价值和风险；若声称可推广到新campaign/板，就需足够独立的采样单元以及与设计匹配的推断。现有布局bootstrap只作为敏感性分析，不能改名为有限样本认证。

原七项合同保留为原稿结果及开发期算术对照。新正式认证的抽样单元、估计目标、缺失完成和有效区间须在评价名单与依赖结构确定后写定，不能仅把旧CP公式换个标签继续使用。

λ增大时，对固定预算的精确最优化，所选集合的**预测**总NULL概率不会增加，预测总收益不会增加；真实NULL数与真实收益没有这个保证。λ=0.2也不是无成本保险。所有原合同条款基于实际事件、价值与样本支持，并非全部基于模型P(NULL)。联合区域覆盖改善不自动等于NULL概率校准。

## 四、生物kernel跨数据实验是正式研究计划，不直接判为无用

目标是学习“什么支持条件下值得启用”，而不是每个数据集事后挑最好的开关。正式对照保留完整generic core，生物是独立、可关闭、支持感知的增量。

### 输入和支持描述量

- 注释覆盖、靶点/MoA逐类关系数及证据类型；未知不编码为无机制。
- 有效邻居数ESS；同时报告未归一化相似度总量、最大相似度和距离，以区别“很多极弱邻居”与真正支持。
- 原始权重总量依赖kernel单位和尺度，不能在不同kernel/数据库间直接使用同一个阈值。先固定相似函数与标准化规则，阈值在训练数据集估计。
- 剂量、时间、细胞背景、测量平台和参考记录匹配度；验证合法性后再分响应、残差尺度或NULL概率用途。

### 训练与外部评价

在一个开发数据集内，用分组内层训练/验证比较core、core+通用参考增量、core+生物增量。借用响应时参考必须有真实响应；借用误差时须有折外/独立残差。关闭生物或无支持时完整输出精确恢复core，不借GENERIC后处理替换原排序。

随后进行dataset/domain-level holdout：用开发数据集的支持描述量和合法折外任务增量确定开关规则，冻结后在未用于决定阈值的数据集检验。留一数据集法是合理选择，但不是唯一有效设计；预定多域开发加一个独立外部域同样可用。不存在“只要3–4个数据集就自动有效”的普适门槛，几个高度相关的子集也不能冒充独立数据集。

启用的证据要对应宣称的用途：响应预测、联合分布校准或实际价值—风险。仅权重显著、关系置换显著或几何MSE较好不能替代任务验证。反过来，数据没有显示增量也不等于生物知识普遍无用。

当前尚未用一致的core+biology配方完成多数据开关规则标定，不能写成“已经在两个数据集标定”。JUMP和LINCS此前不同的结构化kernel、稀疏机制先验和后处理试验不是同一个跨域激活实验。

## 五、JEPA/latent space跨数据实验

2026-09-17更新运行事实：主CORE仍不含JEPA。旧EMA教师式JEPA训练和读出比较属于JUMP source_5；其结果只限制那些实现、划分和目标。LINCS并非“表征未测试”：已完成孔级PCA_STATE、DIRECT_STATE、固定目标条件跨重复CONDITIONAL_STATE对照，以及八臂条件残差信息实验中的DESCRIPTORS_LATENT。LKCP也完成了孔级条件表征迁移诊断。这些实现没有展示足以纳入主规则的稳定任务增量，不能推广为所有表征学习无效。

对应记录为`OPAL2_OPTIONAL_MODULES_RESULTS_20260916.md`及`runs/conditional_residual_information_20260916_v1/REPORT.md`。尚未完成的是原始图像或单细胞集合输入的表征比较，不应与已完成的孔级条件表征混写；CONDITIONAL_STATE也不是旧EMA/VICReg式JEPA的原样重跑。

后续可在已开放DEV上做离线匹配诊断，但这些诊断仍会参与方法开发，不能因为不进入当下主规则就称其使用的数据完全不消耗。不得使用将来正式EVAL对象或其未来孔做自监督预训练。

建议采用共同固定测量目标和同一分布/决策接口，比较：原输入/可靠性基、小型普通非线性表示、带条件的JEPA表示。幅度和条件保留显式旁路；固定目标编码空间或提供已验证防塌缩设计，不强求跨重复完全相同。记录预训练数据、化合物与布局重叠、训练步数、容量与调参预算。

先看跨重复线性读出、幅度保存、有效秩与任务相关误差，再看Γ CRPS、NULL Brier/可靠性、固定预算实际价值与风险。线性探针是诊断，不是排除所有有用非线性表示的定理。不能仅用表示空间自己的MSE与原测量空间R²直接比较。

若后续在LINCS上拟合JEPA，它仍只产生开发证据；完成一个JUMP诊断和一个LINCS诊断，也不自动证明跨数据的启用规则有效。它与生物模块分开研究，避免同时更改两个部件而无法归因。
